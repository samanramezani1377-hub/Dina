# مرکز خطا و لاگ تشخیصی Dina\n\n## هدف\nهر خطای قابل مشاهده API باید یک correlation_id داشته باشد و در PostgreSQL ثبت شود.\n\n## اطلاعات ثبت‌شده\n- شناسه خطا\n- شناسه پیگیری\n- زمان\n- سطح خطا\n- کد پایدار API\n- پیام\n- HTTP status\n- method و path\n- user / organization در صورت قابل تشخیص\n- IP و User-Agent\n- details پس از redaction\n- traceback برای خطاهای داخلی\n- وضعیت حل‌شده و کاربری که آن را حل کرده\n\n## امنیت\nبدنه درخواست، Authorization، Cookie، password، token، API key و داده‌های مشابه ذخیره نمی‌شوند. traceback فقط در مرکز خطای مجاز سازمان نمایش داده می‌شود و هر خطای داخلی در HTTP فقط پیام عمومی و correlation id دریافت می‌کند.\n\n## دسترسی\nمرکز خطا و audit فقط برای owner و manager سازمان در دسترس است و Backend این نقش را enforce می‌کند.\n\n## API\n- GET /api/v1/organizations/{organization_id}/errors\n- POST /api/v1/organizations/{organization_id}/errors/{error_id}/resolve\n- GET /api/v1/organizations/{organization_id}/audit\n\n## رابط کاربری\nهر خطا به‌صورت expandable نمایش داده می‌شود؛ traceback قابل انتخاب است و دکمه «کپی کامل لاگ» تمام اطلاعات تشخیصی امن را یک‌جا برای ارسال به تیم فنی کپی می‌کند.
