# قرارداد خطای API دینا

هر خطایی که سرویس به کلاینت برمی‌گرداند یک شکل واحد دارد و فقط یک شکل:

```json
{
  "error": {
    "code": "journal_not_balanced",
    "message": "total debits must equal total credits",
    "details": {"debit_total": "100", "credit_total": "90", "difference": "10"}
  }
}
```

- `code` بخشی از قرارداد عمومی است. کلاینت روی `code` تصمیم می‌گیرد و **نباید** روی `message` تصمیم بگیرد؛ متن پیام برای انسان است و ممکن است بازنویسی شود. معنای یک `code` هرگز تغییر نمی‌کند، برای خطای دیگری دوباره استفاده نمی‌شود و حذف نمی‌شود.
- `details` همیشه وجود دارد، حتی وقتی خالی است، تا کلاینت برای خواندن آن مجبور به بررسی وجود کلید نشود. `details` فقط شامل واقعیت‌های همین خطاست (مثلاً ارقام نامتوازن) و هیچ داده حساسی نیست.
- پاسخ‌های خطا همواره هدر `X-Correlation-Id` دارند. اگر کلاینت هدر `X-Correlation-Id` یا `X-Request-Id` بفرستد، همان مقدار برگردانده می‌شود؛ در غیر این صورت سرور یک شناسه می‌سازد.
- در پاسخ ۵۰۰ (`internal_error`) همان `correlation_id` داخل `details` هم قرار می‌گیرد و **traceback فقط در لاگ** ثبت می‌شود، نه در پاسخ. پیام پاسخ عمداً کلی است.

مرجع اجرایی این قرارداد `backend/src/errors.py` است و جدول زیر باید همیشه با `ERROR_CODE_STATUS` در آن فایل یکی باشد؛ تست `backend/tests/test_errors.py` این یکی‌بودن را بررسی می‌کند.

## کدها

### اعتبارسنجی درخواست

| code | وضعیت | معنی |
| --- | --- | --- |
| `validation_error` | 422 | بدنه درخواست یا query string با مدل مطابقت ندارد. `details.fields` فهرست فیلدهای نامعتبر با مسیر، پیام و نوع خطاست. |
| `not_found` | 404 | مسیر درخواست‌شده وجود ندارد. |

### قواعد سند حسابداری

| code | وضعیت | معنی |
| --- | --- | --- |
| `journal_empty` | 422 | سند هیچ خطی ندارد. |
| `journal_not_balanced` | 422 | جمع بدهکار با جمع بستانکار برابر نیست. `details` شامل `debit_total`، `credit_total` و `difference` است. |
| `line_must_have_exactly_one_side` | 422 | یک خط سند هم بدهکار و هم بستانکار دارد، یا هیچ‌کدام را ندارد. `details.line_no` شماره خط است. |
| `amount_must_be_non_negative` | 422 | مبلغ بدهکار یا بستانکار منفی است. |
| `journal_immutable` | 409 | سند قبلاً ثبت یا معکوس شده است و دیگر قابل تغییر نیست. |
| `journal_not_reversible` | 409 | تنها سند `posted` قابل معکوس‌سازی است. |
| `entry_already_reversed` | 409 | برای این سند قبلاً سند معکوس ثبت شده است. |
| `invalid_entry_status` | 422 | وضعیت سند خارج از `draft`/`posted`/`reversed` است. |

### سرفصل حساب‌ها و شماره سند

| code | وضعیت | معنی |
| --- | --- | --- |
| `account_not_found` | 404 | حساب در این سازمان وجود ندارد. شناسه حساب متعلق به سازمان دیگر هم دقیقاً همین پاسخ را می‌گیرد تا امکان شناسایی اشخاص دیگر وجود نداشته باشد. |
| `account_code_conflict` | 409 | این کد حساب در همین سازمان قبلاً استفاده شده است. یکتایی در سطح سازمان است. |
| `invalid_account_type` | 422 | نوع حساب خارج از `asset`/`liability`/`equity`/`revenue`/`expense` است. |
| `document_no_conflict` | 409 | این شماره سند در همین سازمان قبلاً استفاده شده است. |
| `journal_not_found` | 404 | سند حسابداری در این سازمان وجود ندارد. |

### سازمان، عضویت و مجوز

| code | وضعیت | معنی |
| --- | --- | --- |
| `organization_not_found` | 404 | سازمان درخواست‌شده وجود ندارد. |
| `not_a_member` | 403 | تماس‌گیرنده احراز هویت شده اما عضو این سازمان نیست. عمداً ۴۰۳ و نه ۴۰۱: چیزی که کم است عضویت است، نه هویت. |
| `permission_denied` | 403 | نقش تماس‌گیرنده پایین‌تر از آستانه لازم (`accountant`) است. نقش ناشناخته هم مانند کمترین نقش و در نتیجه ناموفق رفتار می‌شود. |
| `not_authenticated` | 401 | درخواست هیچ هویت قابل استفاده‌ای همراه ندارد. |

### اعتبارنامه و توکن

| code | وضعیت | معنی |
| --- | --- | --- |
| `invalid_credentials` | 401 | ایمیل یا گذرواژه نادرست است. ایمیل ناموجود و گذرواژه نادرست عمداً یک کد می‌گیرند تا فهرست کاربران لو نرود. |
| `email_already_registered` | 409 | قبلاً برای این ایمیل حسابی ساخته شده است. |
| `token_expired` | 401 | توکن معتبر است اما زمان انقضای آن گذشته؛ کلاینت باید دوباره وارد شود. |
| `token_invalid` | 401 | توکن نامعتبر، دست‌کاری‌شده، با کلید دیگری امضاشده یا با scheme اشتباه ارسال شده است. |

### سایر

| code | وضعیت | معنی |
| --- | --- | --- |
| `internal_error` | 500 | خطای پیش‌بینی‌نشده. پیام عمومی به‌همراه `correlation_id`؛ traceback فقط در لاگ. |
| `trial_balance_unbalanced` | 200 | تنها کدی که داخل پاسخ **موفق** گزارش می‌شود: گزارش تراز بدهکار/بستانکار ارقام واقعی را با `is_balanced: false` برمی‌گرداند و این کد را در همان شکل `{code, message, details}` داخل بدنه می‌گذارد. |

## تغییر این قرارداد

افزودن یک کد جدید مجاز است و باید در `ErrorCode`، در جدول `ERROR_CODE_STATUS`، در همین سند و در
`backend/tests/test_errors.py` اضافه شود؛ تست انتهای `test_errors.py` مقایسه می‌کند که هر کد ثبت‌شده
واقعاً از یک مسیر واقعی کد تولید می‌شود و هر کدی که در این سند آمده در رجیستری وجود دارد. تغییر معنای
یک کد موجود، یا تغییر وضعیت HTTP آن، شکستن قرارداد است.
